# 📊 WRG Dashboard Component

This component implements a standalone, high-performance local web dashboard for the VentoSync system. It provides real-time observability, telemetry graphing, peer mesh visualization, and device control directly from the ESP32-C6 without requiring Home Assistant or internet connectivity for its backend API.

## 📄 File Overview

| File | Description |
| :--- | :--- |
| **`wrg_dashboard.h` / `.cpp`** | **Web Server & REST Controller (`WrgDashboard`)**: Implements the asynchronous HTTP request handler, serving `/` (Frontend, alias `/ui`), `/state` (JSON telemetry, room status, system info & ESP-NOW peers), `/stream` (the same JSON as Server-Sent Events), `/history` (24 h ring buffer, `ventilation_logic/history.h`), `/meta` (limits of the writable settings) and `/set` (thread-safe mutation queue). |
| **`dashboard.html`** | **Frontend SPA**: the single-page application (HTML, Tailwind CSS styling, Chart.js charts from a CDN, dynamic DOM rendering). Edit it directly — `__init__.py` replaces its `<link rel="stylesheet" href="dashboard.css">` with the inlined stylesheet and gzips the result at build time into a flash array (`html_data_id`, ~78 KB + ~15 KB CSS → ~26 KB) that `/` serves with `Content-Encoding: gzip`. |
| **`dashboard.css`** | **Generated, committed** Tailwind stylesheet: only the classes `dashboard.html` uses (minified, ~4 KB gzipped), so the page is styled without internet access (e.g. in the fallback hotspot). Never edit it by hand. |
| **`tailwind/`** | `tailwind.config.js` (theme colors, content = `dashboard.html`), `input.css` and `build_css.sh`, which regenerates `dashboard.css` with the pinned Tailwind v3 standalone CLI (SHA-256 checked, cached in `~/.cache/ventosync`, no Node.js). Run it after changing classes in `dashboard.html` and commit the result; `build_css.sh --check` in `lint.yaml` fails while `dashboard.css` is outdated. Classes built in JavaScript must appear as complete strings in the page, or Tailwind does not find them. |
| **`__init__.py`** | **ESPHome Integration**: Registers `WrgDashboard`. The tables `SENSORS`, `BINARY_SENSORS`, `TEXT_SENSORS`, `NUMBERS`, `SELECTS`, `SWITCHES` and `BUTTONS` map each config option to its JSON key (`add_<type>(key, entity)`); a key exists in `/state` only when its option is configured. Adding a setting: one table entry + the option in `packages/base/ventosync_core.yaml` + a row in `SETTINGS` (`dashboard.html`). |

## ⚙️ Key Mechanisms & Endpoints

- **Threading**: the web server runs in its own task. Entities and the `VentilationController` peer list are only read in `loop()` (main task), which serializes `/state` (every second while a client polled within 15 s or a stream is open) and `/meta` (once) into strings guarded by a mutex; the request handler only copies them. A missing or > 5 s old `/state` answers `503` and the UI retries after 300 ms. The history ring buffer is written by `loop()` (one sample every 10 s) and serialized by the `/history` handler, both under the same mutex.
- **Server-Sent Events** (`/stream`): same mechanism as ESPHome's `/events` — the handler (httpd task) sends the headers and a first chunk, ties a `StreamSession` to the socket (`sess_ctx` / `free_ctx`) and switches it to a non-blocking send; `loop()` adopts the session and sends one chunked `event: state` every 2 s (`STREAM_PUSH_MS`) and right after a `/set` change. A client still busy with the previous event skips one; no progress for 20 s (`STREAM_STALL_MS`) → `httpd_sess_trigger_close()`. Sessions are deleted only after httpd called `destroy()` (fd = 0), so httpd never holds a dangling pointer. Max 3 streams (`MAX_STREAMS`), more → `503`; the UI then polls `/state`.
- **HTTP Endpoints**:
  - `GET /` (alias `/ui`): Serves the responsive web management dashboard. ESPHome's `web_server` also claims `/`; the dashboard wins because it sets up first (`setup_priority::WIFI - 0.5` vs. `WIFI - 1.0`) and the IDF server asks the handlers in registration order. `web_server` stays in the firmware only for the web port that Home Assistant needs for the device's "Visit" link.
  - `GET /state`: Sensor values, Automatik-Status (`auto_status`, `auto_reason`), room status (`room_presence`, `window_guard`, `window_paused`, `vacation_active`, `is_master`), all writable settings under their keys, system info (`sys`: version, variant, mDNS host, uptime, reset reason, RSSI, heap) and the ESP-NOW peers (`mode_index`, `age_s`, `fresh`, room flags, configured phase `phase_cfg`, telemetry, air quality, `host` = mDNS name derived from the peer's MAC when `name_add_mac_suffix` is on). Optional keys only when configured: `voc_index` / `nox_index` / `nox_boost_threshold` (sgp41 variants), `bt_proxy` (Bluetooth proxy variant).
  - `GET /stream`: Server-Sent Events, event `state` = the `/state` JSON every 2 s and after each change.
  - `GET /history`: 24 h of 5-minute averages (`interval_s`, `age_s`, `scale`, `series` with `co2`, `t`, `rh`, `level`, `demand`, `eff`, `t_out`, `t_in`, `t_sup`; fixed point, `null` = no data), see `ventilation_logic/history.h`.
  - `GET /meta`: `numbers` → `[min, max, step]`, `selects` → options, `buttons` → keys, `defaults` → factory value per number key, option index per select key (option `defaults:` in `ventosync_core.yaml`, filled from the `default_*` substitutions). Built once from the entity traits so the UI never duplicates YAML ranges or defaults.
  - `POST /set` (form fields `id`, `val`): Queues a change for `loop()`. CSRF protection: POST only (`405`), header `X-VentoSync` required (`403`). Only keys of configured numbers / selects / switches / buttons; values > 32 characters or non-numeric values for non-selects → `400`; at most 16 pending actions (`MAX_PENDING_ACTIONS`), further requests → `503 Busy`.
  - All endpoints except `/` and `/ui` reject a foreign `Origin` header with `403` (same-origin rule of ESPHome's web server). No login unless `web_server: auth:` is enabled (it covers these endpoints).
- **Charts & history**: **Chart.js** charts (CO2 / level / demand, temperature / relative / absolute humidity, outdoor / extract air / efficiency) for *Live* (browser, 10 min) or *6 h* / *24 h* from `/history`, plus min / mean / max statistics. Connection indicator (stream, polling, lost with data age), request timeouts, toast feedback with verification against the next `/state`.
- **Setup wizard** (0.10.56, grouped in 0.10.58): a modal in `dashboard.html` for floor / room, device ID + phase, then mode + Smart-Automatik and further functions (Klima-Koordination, NOx-Stoßlüftung only with `nox_index`, vacation preset, child lock), defined in `WIZ_GROUPS` and summarized in the same groups. Every row carries a **RAUMWEIT** (room-wide, from the Master) or orange **PRÜFEN** (this device only) badge. It opens by itself while the switch `setup_done` (`setup_done_switch`, `device_config.yaml`, internal) is off **and** floor / room / device ID still equal their `/meta` defaults, otherwise via *Gerätekonfiguration → Einrichtungs-Assistent*. The device step presses `force_discovery` (discovery broadcast + status request) and checks the chosen ID against `/state` `peers[].device_id`; the phase suggestion balances `peers[].phase_cfg` (`ROOM_FLAG_PHASE_B`). Only values that differ from `/state` are sent.
- **ESP-NOW Mesh Observability**: mode, level, direction, freshness, room flags and telemetry of all peer units in the same room.
- **Standalone Operation**: Full control and monitoring are available via any standard web browser using the ESP32's local IP address or mDNS hostname.
